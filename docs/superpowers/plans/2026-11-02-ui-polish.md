## Design and constraints

- Retain the paper/ink/rose identity, team scores, coverage, settings and game information. Use the exact orthogonal 24px external woven border with alternating over/under crossings and square corners.
- Desktop: maximize the intact 5:3 world, hide touch arrows, keep settings easily available, and prevent play-time document scrolling.
- Touch portrait: place the complete arena above a separate two-thumb control deck. Arrange arrows in a cross: up/jump above left/right, down below. Controls remain at least 48 CSS pixels. Use available space for concise guidance, rather than stretching the arena. Portrait always uses the full available width for the framed arena; landscape puts the cross beside it. Use a compact settings icon.
- Retain form labels, natural text editing, visible focus, modal focus containment, and keyboard ownership after connect/resume/reconnect. Release inputs on settings, blur, hidden tabs, resize/rotation and canceled pointers. Multiple fingers on one button must not visually or logically release the other finger.
- Show connecting/cancel/error/disconnected states. Expose waiting/round-result text during play, not only in the hidden settings form. Reset stale scores/timer when disconnected.
- Use dynamic viewport and safe-area padding. Dialog content may scroll internally when needed; the playing document must not scroll. Browser emulation does not prove physical iOS/Android behavior.
- Preserve the classroom networking guide and Docker exercise. No deployment, releases, tags, formal approval review, infrastructure or security-setting changes.
